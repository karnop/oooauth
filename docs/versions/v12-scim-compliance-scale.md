# Version 12: SCIM 2.0 Provisioning, Compliance & High-Scale Resilience

---

## 🎯 1. Objectives & Overview

Version 12 is the capstone production-grade release equipping the auth engine for **hyperscale, enterprise compliance, and zero-downtime operations**:
- **SCIM 2.0 Protocol (RFC 7643 / RFC 7644)**: Automated enterprise employee provisioning and deprovisioning directly from Okta, Azure AD, OneLogin, or Rippling.
- **Enterprise Compliance & Data Governance**: GDPR "Right to be Forgotten" (automated data deletion) & GDPR data export tooling, SOC2-ready access policies.
- **Distributed High-Scale Architecture**: Multi-region read replicas with Redis distributed caching and JWKS CDN edge distribution.
- **Comprehensive Observability**: Prometheus metrics, OpenTelemetry distributed tracing, Grafana dashboards, and structured health/readiness probes.

---

## 📋 2. Functional Requirements

### 2.1 SCIM 2.0 Directory Synchronization
- Conforms strictly to RFC 7644:
  - Users Endpoint (`GET`, `POST`, `PUT`, `PATCH`, `DELETE /v1/scim/v2/Users`):
    - Provision new employee when hired in Okta.
    - Update employee attributes (name, title, department) upon changes.
    - Deprovision / suspend employee immediately when terminated in corporate directory (instantly terminates all active sessions).
  - Groups Endpoint (`GET`, `POST`, `PUT`, `PATCH`, `DELETE /v1/scim/v2/Groups`):
    - Sync corporate teams into organization roles and workspace groups.
  - Service Provider Configuration (`GET /v1/scim/v2/ServiceProviderConfig`).
  - Resource Types & Schemas (`GET /v1/scim/v2/Schemas`).

### 2.2 Compliance & Privacy Tooling
- **User Data Export (`POST /v1/users/me/export-data`)**: Generates an encrypted zip archive containing all user profile records, sessions, identity links, and audit history.
- **Account Deletion / Anonymization (`DELETE /v1/users/me`)**:
  - Permanently removes PII (Personally Identifiable Information).
  - Anonymizes user reference in audit logs while maintaining integrity of historical ledger (`actor_id = 'DELETED_USER_...'`).
- **Data Retention Policies**: Configurable automated purging of expired sessions, dead tokens, and aged audit logs (e.g. 90-day / 365-day retention).

### 2.3 High-Scale Resilience & Edge Caching
- Read/Write splitting: Write operations hit Primary PostgreSQL; high-volume read lookups (JWKS, user profile reads, session verification) route to read replicas.
- Redis multi-tier caching with Stampede protection (`singleflight` pattern in Go).
- Multi-region JWKS CDN distribution: `/.well-known/jwks.json` served via Cloudflare/Fastly edge nodes with `stale-while-revalidate`.

### 2.4 Metrics & OpenTelemetry Instrumentation
- Standardized Prometheus metrics exported at `/metrics`:
  - `auth_requests_total{endpoint, method, status}`
  - `auth_request_duration_seconds_bucket{endpoint}`
  - `auth_active_sessions_gauge`
  - `auth_login_failures_total{reason}`
  - `auth_webhook_deliveries_total{status}`
- OpenTelemetry Distributed Tracing:
  - W3C TraceContext propagation across HTTP headers and async workers.
  - Span instrumentation across database queries, Redis calls, and external IdP HTTP requests.

## 🛡 3. Security & Compliance Standards

| Standard | Implementation |
| :--- | :--- |
| **SCIM Bearer Authentication** | SCIM endpoints secured with dedicated long-lived SCIM Bearer tokens (`scim_tok_...`) generated by organization admins. |
| **Zero-Trust Token Revocation** | When a SCIM user is marked `active: false`, immediately revoke all active sessions, refresh tokens, and cache entries. |
| **SOC2 Audit Trail Completeness**| All administrative actions (including SCIM operations and role grants) logged to tamper-proof audit storage. |

## 🗄 4. Database Schema Migration

```sql
-- 012_create_scim_and_compliance.sql

CREATE TABLE scim_directories (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    organization_id UUID NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
    provider_type VARCHAR(50) NOT NULL, -- 'okta', 'azure_ad', 'onelogin'
    bearer_token_hash VARCHAR(64) NOT NULL UNIQUE,
    is_active BOOLEAN NOT NULL DEFAULT TRUE,
    last_synced_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE scim_user_mappings (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
    directory_id UUID NOT NULL REFERENCES scim_directories(id) ON DELETE CASCADE,
    scim_external_id VARCHAR(255) NOT NULL, -- Okta user ID
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uk_directory_scim_user UNIQUE (directory_id, scim_external_id)
);

CREATE INDEX idx_scim_user_mappings_lookup ON scim_user_mappings(directory_id, scim_external_id);
```

## 🧪 6. Verification & Testing

- **SCIM Conformance Testing**:
  - Run the official OpenSCIM validation test suite against `/v1/scim/v2` endpoints to assert strict compliance with RFC 7643/7644 schemas and error codes.
- **Load & Concurrency Testing (k6 / vegeta)**:
  - Benchmark session verification under sustained 10,000 req/sec load with read replicas and Redis caching.
  - Assert $p99$ response latency $< 15\text{ms}$.
- **Chaos & Disruption Testing**:
  - Simulate Redis node failover -> assert system degrades gracefully by falling back to primary DB lookups.
  - Test instant deprovisioning: Trigger SCIM `active: false` PATCH -> assert in-flight session receives `401 Unauthorized` on next request.
